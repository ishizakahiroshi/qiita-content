![設定はリンクで逃がす](https://raw.githubusercontent.com/ishizakahiroshi/qiita-content/main/public/images/2026-08-05_config-to-drive_hero.png)

設定フォルダのサイズを測ったら 4.3GB ありました。そのうち、本当に守りたいのは 233KB です。

残りは会話の記録と履歴で、消えても作り直せます。というより、**会話のたびに書き換わるので同期に載せると回りっぱなしになる**種類のものです。

この 233KB だけを作業機の外に置きたい。それだけの話が、思ったより長い回り道になりました。結論から書くと、**実体を別ドライブに移して、元の場所はリンクにする**という形に落ち着いています。

![記事の要約](https://raw.githubusercontent.com/ishizakahiroshi/qiita-content/main/public/images/2026-08-05_config-to-drive_infographic.png)

## まず GitHub に置こうとして、27 件で止まった

Claude Code のグローバル設定は `~/.claude` の下に置かれます。ここには自分で書き足したものがけっこう溜まっていました。

- `CLAUDE.md`（全プロジェクト共通の指示）
- `settings.json`
- `memory/`（AI に覚えさせた判断ルール 24 件）
- `guides/`（トリガー別に読ませる詳細ガイド 21 件）
- `commands/` と `scripts/`

合計 56 ファイル、233KB。テキストしかありません。**これは private リポにして履歴を持たせるのが素直だな**と思いました。

そう思って、自作の秘密スキャナを通しました。コミット前に社内固有名詞や個人情報の混入を弾くやつです。

結果は 27 件。しかも**構造 regex の空振りではなく、全部が実質的な検出**でした。内訳は、

- 顧客企業名
- 担当者の氏名
- 社内ホスト名
- アプリのコードネーム
- 家族の姓

これは無理です。1 件ずつ潰すという話でもありません。

## 「秘密が混入した」のではなく、「設計どおりそこにある」

検出結果を眺めて、少し考え込みました。

引っかかったファイルの大半が `guides/` の中の 1 本、**「固有名詞を書く前に必ず台帳を引け」と AI に教えるためのガイド**だったからです。

このガイドは、こういうことを書いてあります。「会社名・人名・サーバー名を書くときは、記憶で書かずに台帳の CSV を引く」「別名で呼ばれることがあるので、呼称の対応表も見る」。

そして、その説明のために**実際の社名と実際の別名を例として並べてあります**。そうしないと AI が「何が対象なのか」を掴めないからです。抽象的に「顧客企業名を確認すること」とだけ書いても、実運用では素通りします。

つまり、**そこに実名があるのは事故ではなく仕様**でした。消したらガイドが機能しなくなります。

ここで GitHub は落ちました。private リポでも、GitHub にコピーが載ることには変わりありません。「消せば上げられる」なら消しますが、消したら使い物にならないものは、そもそも上げる場所を変えるしかない。

![紙に縫い込まれた糸を引き抜こうとして紙が裂ける](https://raw.githubusercontent.com/ishizakahiroshi/qiita-content/main/public/images/2026-08-05_config-to-drive_illustration-by-design.png)

秘密が入っているから困っている、のではありませんでした。**入っていることが正しいものを、どこに置くか**という話に変わったのが、この記事の分かれ道です。

## Google ドライブなら置ける。ただしフォルダ単位でしか指定できない

Google ドライブなら実績があります。サーバーの接続情報を置いたフォルダを、すでに同じやり方で同期していました。作業機の外には出ますが、公開はされません。

そこで `~/.claude` を同期対象に足そうとして、止まりました。**4.3GB です。**

内訳はこうです。

| 中身 | サイズ | 更新頻度 |
| --- | --- | --- |
| `projects/`（セッション記録） | 約 4GB | 会話のたび |
| `file-history/` | 327MB・16,000 ファイル | 編集のたび |
| 設定本体 | 233KB | 週に数回 |

守りたいのは 3 行目だけです。上 2 つは同期しても得がないどころか、常時書き換わるので同期が止まりません。

**Google ドライブ for desktop は、同期対象フォルダの中のサブフォルダを個別に除外できません。** 「このフォルダを同期する」の粒度しかない。だから `~/.claude` を丸ごと指定するという選択肢が消えました。

## コピースクリプトを書いた。動いたけど、毎回手で叩く

最初の解は素直でした。**必要なものだけを別フォルダにコピーして、そこを同期する。**

whitelist を書いて、56 ファイルを別ドライブへコピーするスクリプトを作りました。ハッシュ比較で差分だけコピーするので 2 回目以降は速いし、`projects/` を持っていく事故も起きません。

動きました。動きましたが、**設定を触るたびに自分で叩かないと反映されません。** memory を 1 件足しただけでも、コピーしないとバックアップは古いままです。

「たまに叩けばいい」で済むかというと、たぶん済みません。忘れます。忘れたことにも気づきません。バックアップの一番まずい壊れ方です。

## 実体を別ドライブに置いて、元の場所をリンクにする

方針を変えました。**コピーを作るのではなく、実体そのものを別ドライブへ移して、`~/.claude` 側からはリンクで見せる。**

こうすると、同期対象は「実体のあるフォルダ 1 つ」だけで済みます。コピーもスクリプトも要らない。Google ドライブは実体を直接見ているので、保存した瞬間に同期が走ります。

ここで Windows のリンクの制約に真正面からぶつかりました。**推測で判断すると確実に間違えるところ**なので、一時フォルダで 5 パターン実測しました。

![Windows のリンク 3 種の実測比較](https://raw.githubusercontent.com/ishizakahiroshi/qiita-content/main/public/images/2026-08-05_config-to-drive_fig1.png)

上の表のとおり、**ジャンクションはディレクトリ専用**でファイルには張れません。**シンボリックリンクはファイルにも張れますが管理者権限が要ります**。**ハードリンクは管理者不要ですが同じボリューム内でしか張れません**。今回は `C:` から別ドライブへ逃がしたいので、ハードリンクは最初から使えませんでした。

実際に返ってきたエラーはこれです。

```
ファイルに Junction        → A directory is required for the operation.
ファイルに SymbolicLink    → Administrator privilege required for this operation.
ハードリンク（別ドライブ）  → ファイルを別のディスク ドライブに移動できません。
```

フォルダ 4 本（`memory/` `guides/` `commands/` `scripts/`）はジャンクションで一発でした。管理者権限も要りません。問題は**ルート直下のファイル 6 本**で、この中に `CLAUDE.md` と `settings.json` という一番大事な 2 つが含まれています。

## ショートカット（.lnk）ではダメだった

「ショートカットでいいのでは」と一度考えました。管理者権限も要らないし、Explorer で右クリックすれば作れます。

これは使えません。**Windows のショートカットは `.lnk` という拡張子の付いた別ファイル**で、Explorer が二重クリックされたときに中身を読んで転送してくれているだけです。ファイル API は追いません。

つまりアプリから見ると `settings.json.lnk` という名前の小さいファイルがあるだけで、`settings.json` は存在しないことになります。**リンクに見えるのは Explorer の上だけ**でした。

ファイルを透過的に別の場所へ向けられるのは、Windows では symlink だけです。

## 開発者モードを 1 回オンにしたら、全部つながった

symlink に管理者権限が要ると書きましたが、**例外があります。開発者モードをオンにすると、非管理者でも symlink を作れるようになります。** Windows 10 Creators Update（1703）で入った仕様で、Microsoft の告知にも「管理者が開発者モードを有効にすれば、そのマシンのどのユーザーもコンソールを昇格せずに `mklink` を実行できる」と明記されています（https://blogs.windows.com/windowsdeveloper/2016/12/02/symlinks-windows-10/ ）。

設定 → システム → 開発者向け → 開発者モードをオン。警告ダイアログで「はい」。再起動もサインアウトも不要でした。**開発者モードの切り替え自体には管理者権限が要ります**（https://learn.microsoft.com/ja-jp/windows/apps/get-started/enable-your-device-for-development ）。

有効になったかどうかはレジストリで確認できます。

```powershell
Get-ItemProperty 'HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\AppModelUnlock' |
    Select-Object AllowDevelopmentWithoutDevLicense
# → 1 なら有効。キー自体が無ければ未設定（オフ）
```

これで全部つながりました。最終的な形はこうです。

```
E:\work\.claude\                  実体・58 ファイル 233KB
  CLAUDE.md  settings.json  ほか 6 ファイル       ← Google ドライブはここだけ同期
  memory/  guides/  commands/  scripts/

C:\Users\<name>\.claude\
  CLAUDE.md      → シンボリックリンク
  settings.json  → シンボリックリンク
  memory/        → ジャンクション（フォルダ 4 本とも）
  projects/      実体のまま（4GB・同期対象外）
  file-history/  実体のまま（327MB・同期対象外）
```

**この構成でいちばん効いたのは、設定ファイルの中身を 1 行も書き換えずに済んだことです。**

`CLAUDE.md` には `@~/.claude/local-accounts.md` のような import 行が並んでいて、`settings.json` にはステータスラインのスクリプトが絶対パスで書かれています。ファイルを移してパスを書き換える方式だと、ここを全部追いかける必要がありました。

リンクなら、**アプリは従来どおりのパスを開くだけで、OS が実体まで連れて行ってくれます**。書き換えるものがないので、書き換え漏れも起きません。

## 移行スクリプトは「途中で失敗しても戻せる」形にした

この手の移行は、途中で失敗したときが一番こわいです。**元を消した後にリンクを張れないと、設定が読めない状態でスクリプトが止まります。**

なので順序を工夫しました。

**まず、一時フォルダで symlink を張れるか試します。** 張れなければ 1 ファイルも動かさずに中止します。

```powershell
# 先に一時フォルダで試す。張れないと分かったのがファイルを移した後だと、
# 設定が読めない状態で止まってしまう。
$probe = Join-Path $env:TEMP "link-probe-$PID"
New-Item -ItemType Directory -Path $probe -Force | Out-Null
try {
    $target = Join-Path $probe 'target.txt'
    Set-Content -LiteralPath $target -Value 'probe' -NoNewline
    New-Item -ItemType SymbolicLink -Path (Join-Path $probe 'link.txt') `
             -Target $target -ErrorAction Stop | Out-Null
    $canSymlink = $true
}
catch { $canSymlink = $false }
finally { Remove-Item -LiteralPath $probe -Recurse -Force -ErrorAction SilentlyContinue }
```

**次に、コピーしてハッシュを照合してから元を消します。** ここは別ボリュームであることが効いてきます。同じボリューム内なら `[System.IO.Directory]::Move()` の一発リネームで済みますが、**ドライブをまたぐとこれは使えません**。コピーと削除に分かれる以上、その間に検証を挟めます。

```powershell
Copy-Item -LiteralPath $src -Destination $dst -Recurse -Force

# 消す前に必ず突き合わせる。一致しなければ元は消さない。
if ((Get-TreeHash $src) -ne (Get-TreeHash $dst)) {
    throw "コピー内容が一致しません。元は消しません: $Name"
}

Remove-Item -LiteralPath $src -Recurse -Force
New-Item -ItemType Junction -Path $src -Target $dst | Out-Null
```

**リンク作成で失敗したら、移送先から書き戻します。** ここまでやっておけば、途中で電源が落ちても設定が消えることはありません。

もう 1 つ入れたのが**ジャンクション混入の検出**です。`~/.claude` の下には、サーバーの接続情報や家族の情報へのジャンクションが元から張ってあります。whitelist にこれが紛れると、**リンクの先まで一緒にコピーして Google ドライブへ運んでしまいます**。移送対象を走査する前に、`LinkType` が付いているものがあれば中止するようにしました。

冪等にもしてあるので、何度実行しても壊れません。すでにリンクになっているものは skip します。

## まだ確認できていないこと

正直に書いておくと、**1 つ未検証の点が残っています。**

アプリが設定ファイルを書き換えるとき、上書き方式ならシンボリックリンクはそのまま生きます。ですが**一時ファイルを作ってリネームする方式だと、リンクが実ファイルに置き換わって、実体側と分裂します**。

Claude Code が `settings.json` をどちらの方式で書くのかは、まだ確かめていません。モデルを切り替えるなどして書き換えを起こしてから、リンクが残っているか見る必要があります。

対策は用意してあって、移行スクリプトを再実行すれば検出できます。実ファイルに戻っていて中身が実体側と食い違っていれば、**黙って上書きせず警告で止まる**ようにしてあるからです。

「たぶん大丈夫」と書きたくなるところですが、確かめていないものは確かめていないと書くほうがいいと思っています。

## おわりに

振り返ると、判断が変わった地点は 1 つでした。

最初は「秘密が混ざってしまったので取り除こう」と考えていました。そこから「**取り除いたら壊れるものは、置き場所を変えるしかない**」に切り替わったところで、残りは全部その帰結です。GitHub をやめて Google ドライブにしたのも、コピーをやめてリンクにしたのも。

Windows のリンクは、正直これまで雰囲気で使っていました。「ジャンクションはフォルダ用」くらいの認識で、ファイルに張ろうとして初めてエラーを読みました。実測して表にしたので、次はもう迷わないと思います。

とりあえず 233KB は外に出ました。あとは `settings.json` のリンクが生き残るかどうかを、しばらく様子を見ます。
